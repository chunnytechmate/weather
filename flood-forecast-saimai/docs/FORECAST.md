# โมเดล forecast: วิธีทำนาย พารามิเตอร์ และจุดต่อยอด

ระบบนี้ทำนายระดับน้ำล่วงหน้า 90 วันของสถานีหลักในลุ่มเจ้าพระยา ด้วยโมเดล lag-route hydrograph ที่ผมเขียนด้วย Python stdlib ล้วนๆ ไม่มี pip dependency ตัวเดียว เอกสารนี้เขียนให้คนที่ clone repo ไปต่อยอดหรือวิจัยได้เลย โดยไม่ต้องไล่อ่านโค้ดทั้งหมดก่อน ย้ำก่อน: ทุกค่า forecast ที่ระบบผลิตเป็นการคาดการเชิงสถิติ พารามิเตอร์ตั้งมือ ยังไม่ได้ calibrate กับเหตุการณ์จริง

## Pipeline รายชั่วโมง

cron รันนาที 23 ทุกชั่วโมง (ดูวิธีติดตั้งและถอนใน TOOLS_INSTALLED.md):

```
fetch_snapshot.py     ->  data/snapshots/snapshot-YYYYMMDD-HHMM.json
forecast_days.py      ->  data/fc_days.json (90 วัน)
build_dashboard_v2.py ->  dashboard.html (timeline ย้อนหลัง 60 วัน + คาดการ 90 วัน)
```

`normal_levels.py` รีเฟรชค่าระดับน้ำปกติทุก 24 ชม. (fetch_snapshot เรียกให้เอง) ไปที่ `data/normal_levels.json`

## สมการโมเดลหลัก (forecast_days.py)

```
h(t) = h(t-1) + rise - drain
```

**rise** มี 4 ส่วน:

1. wave จากบางปะอิน: ส่วนเกินเหนือตลิ่งบางปะอินคูณ 0.30 ลากไป 1 วัน (ตัวขับหลักตอนมวลน้ำเหนือไหลลงมา)
2. ฝนเหนือ lag 3 วัน คูณสัมประสิทธิ์ 0.0022
3. ฝนท้องถิ่นวันนั้นคูณ `rain_coef` ของสถานี + momentum (`v0` จากค่าเฉลี่ย 18 ชม. ล่าสุด คูณ e^(-i/1.2) ให้ผลจางไปใน ~2 วัน)
4. น้ำไหลเข้าเขื่อน (เพิ่ม Sep 29, 2026): ผลรวม inflow ของภูมิพล+สิริกิติ์ ถ้าเกิน 150 ล้าน ลบ.ม./วัน = กดดันให้เขื่อนต้องระบาย จะหนุนระดับบางปะอินวันที่ 3-8 ข้างหน้า ด้วยสัมประสิทธิ์ min(0.03, excess/1000) เมตร/วัน ค่าอนุรักษ์นิยมและมี cap เพราะยังไม่ได้ calibrate (ใช้ inflow แทนค่าระบาย เพราะ thaiwater ส่ง `dam_uses_water` เป็นยอดสะสมรายปี ส่วน `dam_released` มีเฉพาะน้ำระบายผ่านทางระบาย ไม่ใช่ยอดปล่อยรวม)

**drain** = `K` × ตัวคูณน้ำหนุน × ส่วนเกินเหนือ floor (`h0 - drop_cap`) และถ้า momentum ติดลบ ระบายเพิ่มอีก `min(0.05, |v0|×0.3)`

ตัวคูณน้ำหนุนคำนวณจากเฟสดวงจันทร์: น้ำแล้ง (neap) = 1.0, spring tide (ข้างขึ้นข้างแรมใหม่) = 0.45 สูตรคือ `1.0 - 0.55 × (1+cos(4π×เฟส))/2`

### พารามิเตอร์ต่อสถานี

| สถานี | K | lag_up | rain_coef | drop_cap |

| สะพานกรุงเทพ | 0.07 | 1 | 0.0005 | 0.7 |

| ท้าย ปตร.คลอง 2 | 0.16 | 1 | 0.003 | 0.9 |

### ฝน 3 tier

- วัน 1-16: NWP จาก Open-Meteo (ความเชื่อมั่นสูงสุดของระบบ)
- วัน 17-35: ECMWF SEAS5 เรียบด้วย rolling mean 5 วัน อ่านเป็นสถานการณ์คาดหมาย ไม่ใช่ค่ารายวัน
- วัน 36-90: SEAS5 ระยะไกลเสื่อมสภาพแล้ว ถือเป็นสถิติฤดูกาล อ่านเป็นแนวโน้มเท่านั้น

แถบ lo/hi กว้าง `±(8 + 9i)` ซม. มีเพดาน 90-100 ซม. แล้วขยายเพิ่มตาม tier: tier 2 เพิ่ม `min(0.30, 0.05×(i-15))` และ tier 3 เพิ่ม `min(0.60, 0.02×(i-34))` รวมสูงสุดราว ±1.9 ม. ที่วันที่ 90

### h0 และ momentum

h0 = ค่าเฉลี่ยค่าอ่าน 18 ชม. ล่าสุด (dedupe ตาม timestamp ของตัวค่าอ่านเอง ไม่ใช่เวลา fetch) เพื่อกลบวัฏจักรน้ำหนุนรายวัน ~±20 ซม. และตัดค่า stale ที่สถานียังไม่อัปเดต

## ระดับน้ำปกติ (normal_levels.py)

ปกติ = median ของค่าเฉลี่ยรายวันจากประวัติ 60 วัน (thaiwater `waterlevel_graph`, 15 นาที/จุด) ตัด 7 วันช่วงเหตุการณ์ออก กรองค่าชำรุด (ต่ำกว่า -1.5 ม.) สถานีที่ระดับขึ้นตามฤดูกาลเกิน 1.5 ม. ใช้ค่ายุคต้นของประวัติ เซ็นเซอร์ กทม. มี 2 เส้นอ้างอิง: ปกติทางสถิติ + เกณฑ์เตือนภัยทางการ (น้ำไม่ท่วมซอย)

## โมเดล scenario ครั้งแรก (forecast_model.py)

water balance ระดับซอยตรงๆ: `depth(t+1) = depth(t) + ฝน×0.35 - อัตราระบาย` เป็นการวิเคราะห์ครั้งเดียวช่วง 27 ก.ย. 2026 (เริ่มโปรเจกต์) รายละเอียดและผล verification อยู่ใน REPORT.md ปัจจุบันระบบใช้ forecast_days.py เป็นหลัก

## ข้อจำกัดที่รู้ตัวอยู่

1. K และ rain_coef ตั้งมืออิงสถิติ recession น้ำหลากปี 2554 ยังไม่ได้ fit จากข้อมูลจริง (คอมเมนต์ใน forecast_days.py ระบุ rain_coef ปรับสเกลใหม่ 28 ก.ย. 2026 เพราะค่าเดิมสูงผิดสัดส่วน)
2. ตัวแปรน้ำไหลเข้าเขื่อนเพิ่มเข้ามาแล้วแต่สัมประสิทธิ์ยังไม่ calibrate และหน่วยข้อมูลเขื่อนของ thaiwater ไม่สม่ำเสมอ: `dam_uses_water` เป็นยอดสะสมตั้งแต่ต้นปี (ภูมิพล ~4,800 ล้าน ลบ.ม. ณ ก.ย. 2026) ส่วน `dam_released` เป็นการระบายรายวันผ่านทางระบายเท่านั้น ต้องอ่านระวัง
3. ตัวคูณน้ำหนุนมาจากเฟสดวงจันทร์ (ดาราศาสตร์) ไม่ใช่ tide table จริงของกรมเจ้าท่า ที่มีปัจจัยลมฟ้าอากาศและ topology ปากแม่น้ำด้วย
4. ประวัติ snapshot เริ่ม Sep 27, 2026 ยังสั้นเกินกว่าจะ backtest หรือ train โมเดล ML ได้เต็มรูปแบบ
5. ครอบคลุมแค่ลุ่มเจ้าพระยา ลุ่มน้ำอื่นและเขื่อนต่างประเทศยังไม่มีในโมเดล (ข้อมูลเขื่อนในประเทศเริ่มเก็บแล้วใน `dams_all`)
6. วันที่ 36-90 คือสถิติฤดูกาล ไม่ใช่พยากรณ์ ใช้ตัดสินใจเชิงวันไม่ได้ ใช้ดูภาพรวมแนวโน้มเท่านั้น

## แนวทางทำให้แม่นขึ้น เรียงตามความคุ้มค่า

1. **fit พารามิเตอร์จาก snapshots ที่สะสม** เมื่อมีข้อมูล 30 วันขึ้นไป ใช้ least squares หา K และ rain_coef ต่อสถานี แทนค่าตั้งมือ นี่คือก้าวที่ให้ผลมากที่สุดเพราะข้อมูลระดับจริง 15 นาที/จุด มีอยู่แล้วใน `data/snapshots/`
2. **calibrate ตัวแปรน้ำไหลเข้าเขื่อน** โครง dam_push เข้าโมเดลแล้วตั้งแต่ Sep 29, 2026 แต่ lag 3-8 วันและสัมประสิทธิ์ยังเป็นค่าเดาอนุรักษ์นิยม ต้อง fit จากเหตุการณ์จริงเมื่อมีวันที่เขื่อนระบายหนักให้เทียบ
3. **เทียบกับ forecast สากล** เป็น baseline: Copernicus GloFAS (river discharge ราย 6 ชม. ล่วงหน้า 30 วัน) และ Google Flood Hub ดูรายละเอียดและลิงก์ใน DATA_SOURCES.md
4. **ใช้ tide table กรมเจ้าท่า** แทนการคำนวณจากเฟสจันทร์
5. **โมเดล ML** (LSTM หรือ gradient boosting) เมื่อสะสมข้อมูลครบ 1-2 ฤดูน้ำ ตัวแปรตั้งต้นคือระดับ 18 ชม. + ฝน NWP + release เขื่อน + tide
